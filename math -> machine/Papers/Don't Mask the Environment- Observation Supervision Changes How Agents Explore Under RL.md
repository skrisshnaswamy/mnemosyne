## The Core Idea

An agent trajectory is a conversation between two speakers. The agent writes an action ("run this command"), the environment writes back an observation ("here is the terminal output"). Standard supervised fine-tuning of agents throws away half of that. The loss is applied only to the tokens the agent wrote; the observation tokens sit in the context window as input, but they are masked out of the prediction target. The reasoning seems obvious — at deploy time the model emits actions, never observations, so why train it to produce text it will never produce?

The finding here is that this reasoning is wrong, and wrong in a way you cannot see until you run reinforcement learning afterwards. **ActObs** simply unmasks the observation tokens and applies the same next-token loss to them. No new data, no new parameters, no extra tokens in the sequence, no extra forward passes, no change to the RL algorithm. It is a one-line change to the label mask.

Immediately after SFT, this does almost nothing — the three SFT checkpoints score within noise of each other on Terminal-Bench 2.0. Then you run identical GRPO on each, and they separate. On Qwen3-4B, GRPO from the ActObs checkpoint beats GRPO from the action-only checkpoint at every sampling budget: 7.2 vs 5.6 pass@1 (+29% relative), 19.1 vs 18.0 pass@16. On Qwen3-8B it trades single-shot reliability for coverage: worse pass@1 (11.0 vs 12.3) but +3.4 points at pass@16 (27.0 vs 23.6) and 24 tasks solved instead of 21. On aider-polyglot, a code-editing benchmark that appears in neither the SFT corpus nor the RL task set, the 4B ActObs policy hits 13.9 pass@1 vs 9.7 — a 43% relative gain — *despite starting from a weaker aider checkpoint before RL*.

> [!NOTE] ActObs
> Supervised fine-tuning on agent trajectories where the loss covers both agent-authored action tokens **and** environment observation tokens. Predicting $o_t$ given $(h_t, a_t)$ forces the model to represent what an action does to the world, using text that is already in the training sequence for free. ^actobs

Why this unlocks something: it reframes the SFT checkpoint not as "a policy with some score" but as *a distribution that RL has to work with*. Two checkpoints can be equally good and yet one gives exploration room and the other does not. The paper's mechanism story is that action-only training specialises one-sidedly — it sharpens the single teacher command while letting the model's pretrained knowledge of action consequences rot away, below even the base model's level. Joint supervision blocks that specialisation, and what survives is probability mass on plausible command variants that repeated sampling can then find.

## The Methodology

**The objective.** A trajectory is $\tau = (x, a_1, o_1, \ldots, a_T, o_T)$, where $x$ is the task prompt, $a_t$ is an assistant turn (reasoning plus commands), $o_t$ is the verbatim terminal output. With $\mathcal{A}$ the action-token indices and $\mathcal{O}$ the observation-token indices:

$$\mathcal{L}_\lambda(\theta) = -\frac{\sum_{i\in\mathcal{A}}\log p_\theta(y_i \mid y_{<i}) + \lambda\sum_{i\in\mathcal{O}}\log p_\theta(y_i \mid y_{<i})}{|\mathcal{A}| + \lambda|\mathcal{O}|}$$

$\lambda = 0$ is standard action-only SFT ("ActionSFT"); $\lambda = 1$ is default ActObs. The denominator keeps the per-example loss scale constant as $\lambda$ moves, so you are not secretly changing the effective learning rate. Prompt tokens stay masked in both. This is plain [[Cross Entropy]] on more positions.

**Data.** One corpus for everything: 50k multi-turn terminal trajectories (0.71B tokens) from the synthetic split of Nemotron-Terminal-Corpus, generated by DeepSeek-V3.2. Observation tokens are ~45% of the corpus, so ActObs roughly doubles the number of supervised positions.

**SFT.** Qwen3-4B and Qwen3-8B, one epoch, 781 steps, batch size 64, cosine schedule, peak LR $10^{-5}$. The methods differ *only* in the loss mask.

**RL.** GRPO for 135 steps on 2,392 containerised tasks from Endless Terminals (disjoint from the SFT corpus), binary verifier rewards, 16 rollouts per task, batch 32, LR $10^{-6}$. Plain GRPO has no observation loss at all — the observation supervision lives entirely in the initialisation.

**Baselines and controls.**
- **Obs→Act** — a timing control. One epoch of observation-only SFT, then one epoch of action-only SFT. Same total observation exposure, but *sequential* rather than joint.
- **ECHO** — an RL-side comparison that adds a next-observation prediction loss (weight 0.05) on the policy's own rollouts during GRPO.

**Evaluation.** Terminal-Bench 2.0 (89 tasks, terminus-2 reference agent, official wall-clock limits), 16 attempts per task, pass@$k$ via the unbiased Codex estimator. Serving is pinned: one vLLM engine, TP=8 on A100s, 12 concurrent trials, 40,960-token context, $T=0.6$, top-$p$ 0.95, top-$k$ 20. This pinning matters because Terminal-Bench limits are wall-clock, so serving latency is part of the benchmark. Error bars are one bootstrap standard error over 20,000 resamples, holding the task set fixed and resampling attempts within tasks.

> [!NOTE] pass@k
> The probability that at least one of $k$ independent attempts solves a task, estimated without actually drawing $k$ samples per estimate. Here it is the central metric because the whole claim is about *exploration* — pass@1 measures reliability, high-$k$ pass@$k$ measures how much of the solution space the policy can still reach. ^pass-at-k

## Ablation Studies and Experiments

**The headline separation.** After SFT the checkpoints are boring: 4B pass@1 is 4.5 / 4.4 / 4.4 for ActionSFT / ActObs / Obs→Act. After identical GRPO, 4B pass@1 is 5.6 / 7.2 / 5.3. At 8B, the *gain* from RL tells the story better than the absolute score:

| 8B init | Δpass@1 | Δpass@4 | Δpass@8 | Δpass@16 |
|---|---|---|---|---|
| ActionSFT | +3.1 | +0.5 | −1.0 | −1.1 |
| ActObs | +3.1 | +3.2 | +3.9 | +4.5 |
| Obs→Act | +3.6 | +3.4 | +1.9 | −1.1 |

GRPO from action-only SFT *destroys* high-$k$ coverage — it concentrates mass on rewarded paths and loses rare solutions. This is the known RLVR contraction (see [[Locked at the Entrance, Open Inside- Where RLVR Narrows the Solution Space]]). ActObs limits the contraction.

**What did not work — and this is the useful part:**

- **Observation-only SFT scores 0.0.** So does action-SFT-then-observation-only-SFT. Predicting the world is not a substitute for imitating the expert; it is a complement.
- **Sequential supervision (Obs→Act) fails.** Same amount of observation signal, delivered in a separate phase, gives up 2.2 points (4B) and 3.4 points (8B) at pass@16 versus joint training. Joint optimisation, not exposure, is the mechanism.
- **A second epoch of action-only SFT (act2act) tracks ActionSFT.** More optimisation does not recover the effect.
- **Observation supervision only for the first 100 steps (ActObs-100)** reaches 19.1 pass@8 after GRPO vs 23.6 for full ActObs. The observation loss keeps earning its keep through the whole run.
- **Shuffled observations** — pairing each action with an observation from a different trajectory — collapses pass@1 from 7.9 to 3.7. Interestingly, it *reproduces the entropy signature* of ActObs (self-entropy 0.702, flat command margin) while performing terribly. Flat distributions alone are not the thing.
- **"Wild logs"** — token-and-format-matched production logs unrelated to the action — retains 7.9 pass@1 but reproduces neither the entropy effect nor the benefit.
- **Salient-filtered observations** (stripping command echoes, repeated lines, scaffold text) is *worse* than supervising the full raw terminal response.
- **Raising temperature to match entropy does not work.** Setting ActionSFT→GRPO to $T^*=0.64$ so its self-entropy matches ActObs→GRPO changes pass@1 through pass@16 by at most 0.7 points, solves zero additional tasks, and leaves the pass@16 gap intact. The advantage is in the learned distribution, not in injected randomness. See [[Sampling Parameters]].
- **ECHO has higher entropy but loses.** Adding next-observation loss during RL produces the highest endpoint entropy in the table, yet ActObs→GRPO beats ActObs→ECHO at 8B pass@16 (27.0 vs 24.7) and solves more tasks (24 vs 22). Entropy magnitude is not the causal variable.

**The $\lambda$ sweep shows a graded trade, not a switch.** At 8B, as observation weight rises, post-GRPO pass@8 goes 21.0 → 21.3 → 22.5 → 23.6 for $\lambda \in \{0, 0.05, 0.25, 1\}$, while pass@1 goes 12.3 → 11.4 → 11.0 → 11.0. Critically, $\lambda = 0.25$ has an SFT checkpoint essentially identical to ActionSFT at pass@1 and pass@4, yet its post-GRPO pass@8 is already 1.5 points higher. The command-token top-1-to-top-2 logit margin shrinks monotonically with $\lambda$ (−0.29 at 0.05 down to −0.52 at 2.0) even while the SFT benchmark score is flat — the distribution is changing where the score is not looking.

**The gradient mechanism.** At every saved SFT checkpoint they compute the action-token gradient $g_{\mathrm{act}}$ and observation-token gradient $g_{\mathrm{obs}}$ separately on the same 256 held-out trajectories (for ActionSFT, $g_{\mathrm{obs}}$ is a diagnostic only — it was never applied). Decompose:

$$g_{\mathrm{obs}} = r\lVert g_{\mathrm{act}}\rVert\left(c\,\hat{g}_{\mathrm{act}} + \sqrt{1-c^2}\,\hat{g}_{\mathrm{act}}^{\perp}\right)$$

with $c = \cos(g_{\mathrm{obs}}, g_{\mathrm{act}})$ and $r = \lVert g_{\mathrm{obs}}\rVert / \lVert g_{\mathrm{act}}\rVert$. At the pretrained checkpoint $c = 0.83$ — the two updates mostly agree. Within 10–20 SFT steps $c$ falls to the noise floor and stays there. After that, action-only updates carry *no* information about the observation objective. The norm ratio then diverges: under ActionSFT $r$ climbs to about **41** (action gradient shrinks as it fits the demonstrations, observation gradient stays large and unaddressed); under ActObs $r$ stays near **0.5**.

> [!NOTE] Gradient orthogonality at the SFT-to-RL handoff
> Two auxiliary losses that start aligned can decouple almost immediately. Once $\cos(g_1, g_2) \approx 0$, optimising one is no longer a proxy for the other, and the unoptimised objective can actively degrade. Measuring this cosine over training is a cheap diagnostic for whether a masked-out loss term is doing anything. See [[Derivative#Gradient|gradient]] and [[Backpropagation]]. ^gradient-orthogonality

Functionally, ActionSFT ends up predicting terminal feedback *worse than the base model* across most of the sequence. ActObs improves on the base model not just at the fixed `New Terminal Output:` wrapper (the trivially memorisable prefix) but at later positions and on shell prompts, error lines, and other payload text.

**Where the entropy actually sits.** Bucketing command-token entropy by position: after GRPO, ActObs and ActionSFT are equally sharp on the *first* command tokens. The separation opens up later in the command — where arguments, flags, and paths live. ActObs does not make the agent less decisive about *which* tool to call; it keeps variation in *how* the call is instantiated. The case study is vivid: on `qemu-startup`, every method issues the same canonical QEMU launch, but the ActObs policy sweeps one launch parameter at a time across twelve distinct invocations, varying guest memory `-m 128M → 512M → 1024M`. The 128 MiB default cannot boot the image. No lower-entropy policy ever samples that variation.

**Movement vs entropy.** Measuring $\mathrm{KL}(\pi_{\mathrm{init}} \| \pi_{\mathrm{final}})$ at action tokens on 200 fixed Terminal-Bench traces, ActObs→GRPO has the *smallest* endpoint displacement from its own initialisation, the highest retained self-entropy (0.779 vs 0.716), and the best pass@16. Obs→Act moves farthest and retains the least. So RL had to reallocate less probability mass, and left more of the starting distribution within reach of resampling. Connect to the [[KL Divergence|KL]] leash discussion in [[RLHF]].

**Coverage vs concentration.** ActionSFT→GRPO produces 175 successes spread over 21 tasks (8.33 per solved task). ActObs→GRPO produces *fewer* total successes — 156 — but over 24 tasks (6.50 per task), with higher "win entropy" (4.16 vs 4.05 bits). It solves three tasks that no SFT policy and no ActionSFT→GRPO attempt ever solves.

## Worth Remembering

- **GRPO collapses repetition regardless of initialisation.** Exact command repeats per trajectory drop from 34.9–48.1 (SFT) to 1.0–1.2 (post-RL); the "retry the identical command after an error" rate drops from 48–55% to under 1%. That is a big, consistent, method-independent effect of RL on agent behaviour and worth filing separately from the ActObs claim.
- **Successful ActObs trajectories are shorter even though overall trajectories are longer.** At 8B SFT: median 59 steps overall (vs 51 for ActionSFT) but median 13 steps on *successful* attempts (vs 21). More persistence on hard tasks, more directness on solvable ones.
- **Doubling the agent wall-clock budget helps every observation-supervised checkpoint and only those.** ActObs SFT pass@1 goes 7.9 → 10.1; ActionSFT goes 9.2 → 7.9. More interaction time is only useful if the policy has somewhere new to go.
- **An SFT benchmark score is a bad proxy for SFT checkpoint quality when RL follows.** This is the transferable lesson. If you are selecting an SFT checkpoint for downstream RL, pass@1 on the eval set is nearly uninformative; entropy at argument positions, top-1/top-2 margin, and high-$k$ pass@$k$ carry the actual signal.
- **Limitations the authors own:** terminal agents only (aider-polyglot is the one cross-domain probe); Qwen3 only, so 4B vs 8B is a scale comparison but not a family comparison — shared tokenizer and chat template; a single teacher (DeepSeek-V3.2); and scaffold mismatch between SFT, RL, and eval (RL uses a fresh non-interactive shell, Terminal-Bench uses a persistent `tmux` session), which makes absolute SFT-vs-RL comparisons shaky even though within-stage comparisons are controlled.
- **Practical caveat:** ActObs costs nothing at training time, but it is *not* free at 8B — you give up ~1.3 points of pass@1 to gain 3.4 at pass@16. If your product does one shot per user request, this is a loss. If you have a verifier and can sample $k$ times, it is a clear win. The $\lambda$ sweep gives you a dial: $\lambda = 0.25$ buys most of the pass@8 gain with an SFT checkpoint indistinguishable from action-only.
- **Open question worth chasing:** entropy is clearly correlated with the effect but demonstrably not sufficient (shuffled-obs reproduces the entropy signature and fails; ECHO exceeds the entropy and loses). The real variable is something like "probability mass on *correct-in-context* alternatives", which nobody here measures directly. A cleaner statement of that quantity would make this paper much stronger.
